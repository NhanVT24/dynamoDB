# VNPay IPN: diagnosis and verification

## Observed AWS evidence

Read-only inspection on 2026-09-08 found the following request in
`/aws/lambda/supermarket-http-api-aws` at 2026-09-07 10:05:57 UTC
(17:05:57 Vietnam), request ID `7f5cab62-4426-4099-a00f-4387fd9acea0`:

- Route: `/api/payments/vnpay/ipn`.
- `vnp_TxnRef=222222`, `vnp_Amount=1000000`.
- `vnp_TmnCode=2HY1RX82` matched the running Lambda's merchant.
- `vnp_SecureHashType=HMACSHA512`, but the supplied hash was **9 characters**.
- `vnp_ResponseCode=00`; `vnp_TransactionStatus` was absent.
- Recomputing HMAC-SHA512 with the running Lambda configuration did not match.

A SHA512 HMAC encoded as hex requires 128 characters. This request cannot
pass verification; returning `97` is correct. No secret or complete signature
was printed or saved during this inspection. This describes that observed
request, not every future request generated by the VNPay portal.

The supplied `NX1788834010694` URL fragment was a payment-creation URL, not a
complete IPN. Its signature cannot be reused to sign a different IPN payload.

## Changes

- IPN alone updates payment state. `/return` verifies its signed query and
  reads that transaction's persisted state; it does not publish events.
- Result page polls the read-only endpoint while state is pending. Backend
  payment/order processing continues if the browser is closed.
- Verify scalar `vnp_*` fields, ignore unrelated metadata, exclude signature
  fields, sort and encode once, validate 128-character hex, compare in constant time.
- Validate merchant, callback fields, exact integer amount and both response
  and transaction status. A signed creation request cannot finalize a payment.
- Conditional DynamoDB update records the outcome before notification work.
  Consistent reads resolve concurrent callbacks. Dispatch failures, disabled
  EventBridge publishing and DB errors return `99`. Duplicate callbacks resume
  unfinished dispatch before `02`. Both successful and failed events recover.
- A late paid callback remains paid. Order workers retain their reservation
  checks and existing alert/retry/DLQ path for paid orders that cannot be fulfilled.
- No-email standalone sessions still record payment. Checkout sessions missing
  customer email record payment but return `99` and log reconciliation required.
- Diagnostic logs report keys, hash length, verification reason and merchant
  match without logging the signature, secret or complete callback URL.

## Local tests — no AWS/VNPay writes

Requires Node 24 (the tested runtime):

```powershell
npm run test:vnpay -w @supermarket/api
```

The suite invokes the real Nest controller with Fastify HTTP injection and
an in-memory DynamoDB/EventBridge substitute. It covers checksum/encoding,
duplicates, amount/merchant mismatch, missing email, expiry, Return/IPN ordering,
concurrency and event/DB failures. It does not prove a deployed API Gateway or
real DynamoDB transaction works end to end.

Save a **complete** callback URL or query to a private local file outside git,
then inspect it offline with the local environment's secret:

```powershell
npm run diagnose:vnpay -w @supermarket/api -- C:\temp\vnpay-callback.txt
```

The command makes no HTTP calls and prints no signature/secret. A fragment of
a creation URL will show missing callback fields and/or a checksum mismatch.

## Deploy and sandbox verification

Deploy the reviewed backend changes using the existing deployment process
(`npm run deploy:aws`) and restart/redeploy the frontend. Source edits do not
change the running Lambda. Infrastructure was not modified by this fix.

Keep the portal's configured IPN endpoint as the backend `/ipn` HTTPS URL with
GET and HMACSHA512. Return URL may point at the local frontend for development;
VNPay IPN must reach the public backend independently of that frontend.

1. Create a new checkout through the application, obtaining a real stored
   `NX...` session. Complete a sandbox payment. Close the browser before the
   redirect for one test to verify backend independence.
2. In the actual receiving Lambda's CloudWatch logs, find
   `vnpay.callback_checked` with `source=ipn`, matching `txnRef`,
   `hashLength=128`, `reason=verified`, `merchantMatches=true`.
3. Expect HTTP 200 JSON `RspCode=00` once payment state and required event
   dispatch have completed. A failure/cancellation can also be ACKed `00`:
   this acknowledges receipt, not successful payment.
4. Check `PAYMENT#<txnRef>/DETAIL`: status, response code, gateway transaction
   status, transaction number, and `paymentEventEnqueuedAt`. For checkout,
   also verify order creation, reservation consumption and worker/DLQ results.
5. Repeat the same signed IPN only on an authorized sandbox test session:
   expect `02` after prior processing. An invalid signature must remain `97`.

If the portal's **Test call IPN** still supplies a 9-character hash or omits
transaction status, correct its test data/use a real sandbox payment, or ask
VNPay support to provide a valid HMACSHA512 IPN test. Do not add an unsigned
probe exception returning payment ACK `00`. A correctly signed test referencing
an order that does not exist should return `01`, not `00`.

## Remaining operational boundaries

This patch repairs the existing VNPay retry mechanism; it does **not** add a
transactional outbox dispatcher. Payment state and event metadata are durable,
but recovery of an unmarked event currently needs an IPN retry/manual replay.
VNPay documents at most 10 attempts, 5 minutes apart. A sustained outage beyond
that window requires reconciliation. Event publication is at least once:
publish succeeding followed by marker-write failure can publish again.
Order creation uses its existing conditional transaction, but duplicate
notifications/emails remain possible in the existing consumer. A durable outbox
dispatcher and consumer deduplication are separate follow-up work, not guarantees
provided by this patch.

Legacy records already finalized as expired/failed by the previous Return URL
logic are not silently rewritten by contradictory callbacks. They return `99`
and require payment reconciliation. No automatic refund or inventory override
is performed.

Official protocol reference:
https://sandbox.vnpayment.vn/apis/docs/thanh-toan-pay/pay.html
